# mini_autotune 工作流程

| 项 | 内容 |
|---|---|
| 文档版本 | v0.1（草稿） |
| 日期 | 2026-11-17 |
| 状态 | 待评审 |
| 关联文档 | `docs/REQUIREMENTS.md`、`docs/DECISIONS.md`、`docs/REVIEWS.md`、`CLAUDE.md` |

## 1. 目的

定义 mini_autotune 从需求到下单的角色、阶段门、评审节点与变更规则，保证：

- 每一步有明确产出物和通过条件；
- 写的人不自审，评审有记录、可追溯；
- 花钱动作（下单）只在全部前置门通过后发生。

## 2. 角色与职责

| 角色 | 是谁 | 职责 | 决策权 |
|---|---|---|---|
| **鼠王** | 产品负责人、出资人 | 确认需求与验收标准；拍板待确认项；确认预算、样板数量、外壳与修音口味 | 最终产品决策；唯一批准下单/付款 |
| **AI** | 本项目内的 Claude（文档、设计执行） | 需求整理、方案设计、原理图/PCB（经 `jlceda` skill）、BOM 初稿、文档维护、评审包准备、问题修订 | 技术建议；无评审签字权；不得下单 |
| **Claude B** | 独立评审实例（与撰写方隔离） | 原理图、BOM、布局的预审；逐条给出发现项与严重度 | 预审否决：阻塞项未关闭不得提交终审 |
| **工程师朋友** | 人类硬件工程师 | 原理图/布局/DFM/安全终审；给出可制造性意见 | 终审签字；未签字不得过门 |

规则：

- **写的人不评审自己的产出。** AI 写的文档/设计，由 Claude B 预审、工程师朋友终审。
- AI 不得代签，不得把 Claude B 的预审结论写成终审通过。
- 鼠王可以否决任何技术建议；技术可行性由工程师朋友会签。
- 预审与终审冲突时，用实际检查（ERC/DRC/实测/规格书）裁决，不按人头。

## 3. 阶段门总览

```
需求 --[G0]--> 原理图 --[G1]--> 评审(Claude B 预审 -> 工程师终审) --[G2]-->
BOM --[G3]--> 布局 --[G4]--> 评审(Claude B 预审 -> 工程师终审) --[G5]-->
鼠王确认 --[G6]--> 下单
```

| 门 | 阶段 | 准入条件 | 准出物 | 通过条件 | 批准人 |
|---|---|---|---|---|---|
| **G0** | 需求冻结 | 需求文档完成 | `docs/REQUIREMENTS.md` v1.0 | 全部 MUST 有可测验收标准；待确认项已关闭或明确降级并记录；风险 RISK-01 已裁决 | 鼠王 |
| **G1** | 原理图完成 | G0 通过 | 嘉立创 EDA 原理图工程、ERC 报告、自检清单、电源树、接口表 | ERC 无错误；自检清单全过；关键器件封装核对 | AI 自检（不代表评审） |
| **G2** | 原理图评审 | G1 完成；评审包齐备 | `docs/REVIEWS.md` 中的原理图评审记录 | Claude B 预审完成并逐条回应；工程师朋友终审签字；阻塞项 = 0 | 工程师朋友 |
| **G3** | BOM 完成 | G2 通过 | BOM 表（含单价、库存、替代料）、成本核算表 | 全部物料可采购；成本 ≤ Q-01；封装/极性核对 | AI 自检 + 鼠王确认预算 |
| **G4** | 布局完成 | G3 完成 | PCB 工程、DRC 报告、3D 预览、尺寸/净空检查表 | DRC 无错误；尺寸 ≤ ID-1；天线净空、麦克风开孔、扬声器腔体、按键、电池仓检查通过 | AI 自检（不代表评审） |
| **G5** | 布局评审 | G4 完成；评审包齐备 | `docs/REVIEWS.md` 中的布局评审记录 | 同 G2：预审 + 终审 + 阻塞项 = 0 | 工程师朋友 |
| **G6** | 下单 | G5 通过 | Gerber、BOM、坐标文件、工艺说明、订单号 | 鼠王明确确认数量、工艺、金额、交期；文件包复核无误 | 鼠王 |

> G1/G4 的「自检」只是提交评审前的准备，不是评审，不得写进 `docs/REVIEWS.md` 当作通过记录。

## 4. 各阶段说明

### 4.1 需求（G0）

- 产出：`docs/REQUIREMENTS.md`。
- 必查：每条 FR/NFR 是否有可测验收标准；「待确认」是否列全并标明阻塞阶段；风险是否有缓解方案。
- 需求冻结后，新增/修改需求走变更流程（第 6 节），并重新过 G0。

### 4.2 原理图（G1）

- 工具：嘉立创 EDA，**一律通过 `jlceda` skill** 操作。
- 产出：原理图工程、ERC 报告、电源树、接口定义、关键器件封装核对表。
- 自检重点：电源树与去耦、I2S 时钟/数据、麦克风 L/R 与电源、DAC/功放使能与滤波、按键上拉与 ESD、RGB 电平、USB-C CC 电阻、电池保护、测试点、封装。
- 自检完成后提交评审包：工程版本/路径、ERC 报告、自检清单、已知问题列表。

### 4.3 评审（G2）

1. AI 提交评审包，**不自行判定通过**。
2. Claude B 预审：按 `docs/REVIEWS.md` 检查清单逐项检查，输出发现项（阻塞/重要/建议）。
3. AI 逐条修订或给出书面理由；阻塞项必须关闭。
4. 工程师朋友终审：确认关键设计、可制造性、安全；签字。
5. 评审记录写入 `docs/REVIEWS.md` 并 git commit；口头结论无效。

### 4.4 BOM（G3）

- 产出：BOM 表（料号、规格、封装、数量、单价、库存、替代料、贴片方式）。
- 必查：关键件（ESP32-S3 模组、INMP441、DAC/功放、连接器、电池、保护器件）有货且封装正确；成本符合 Q-01；成本口径符合 Q-11。
- BOM 中每个料号尽量来自嘉立创基础库/常备库存；非标件标注采购渠道与交期。

### 4.5 布局（G4）

- 工具：嘉立创 EDA，经 `jlceda` skill。
- 产出：PCB 工程、DRC 报告、3D 预览、尺寸与结构检查表。
- 自检重点：板框 ≤ 85.60 × 53.98 mm；安装孔与外壳匹配；天线净空；麦克风开孔/密封/减振；扬声器腔体与开孔；按键间距；电池仓；USB-C 位置；电源回路与地平面；ESD；丝印与极性。
- 完成后提交布局评审包。

### 4.6 评审（G5）

流程同 G2，检查清单换成布局清单。重点：结构干涉、声学隔离（RISK-03）、功放噪声（RISK-06）、可装配性、DFM。

### 4.7 下单（G6）

- 前置：G5 通过；鼠王确认数量（Q-02）、工艺、金额、交期。
- 文件包：Gerber、BOM、坐标文件、工艺说明、拼板/阻抗要求（如需要）。
- 下单动作属于外部副作用，**必须鼠王明确确认后才执行**；headless 运行只准备文件包并报告，不执行下单。
- 下单后记录：订单号、数量、金额、预计交期、下单文件版本（git tag）。

## 5. 文档与版本

- 文档是唯一事实源，代码/工程以 git 管理。
- 每个门通过后打 tag：`gate/G0`、`gate/G2`、`gate/G5`、`gate/G6`（示例命名，实际以仓库约定为准）。
- 修改已有文件前做带时间戳备份（见 `CLAUDE.md`）。
- 评审记录、ADR、需求变更必须进 git，不能只留在聊天记录里。

## 6. 变更管理

任何过门后的变更按以下流程：

1. 提出变更：说明原因、影响范围（需求/原理图/BOM/布局/成本/交期）。
2. 影响分析：AI 给出受影响的需求 ID、ADR、评审项。
3. 重新评审：受影响的门重新执行；架构级变更必须新增或更新 ADR。
4. 记录：`docs/REVIEWS.md` 增加变更评审记录；需求版本号递增。
5. 涉及成本、数量、交期的变更，必须鼠王确认。

## 7. 评审节点说明（Claude B 预审 / 工程师朋友终审）

| 项 | Claude B 预审 | 工程师朋友终审 |
|---|---|---|
| 目的 | 在人工终审前把明显问题挖干净 | 对设计负责，给出可制造性与安全结论 |
| 输入 | 评审包（工程版本、报告、自检清单、已知问题） | 预审记录 + 修订后的评审包 |
| 输出 | 发现项列表（严重度、位置、建议） | 结论（通过/有条件通过/驳回）+ 签字 |
| 权限 | 阻塞项未关闭则不得提交终审 | 唯一终审签字人 |
| 记录 | 写入 `docs/REVIEWS.md` | 写入 `docs/REVIEWS.md` |

- 预审发现项必须逐条回应：修复、或书面说明不修的理由并由终审确认。
- 终审可以在预审清单之外新增发现项。
- 「有条件通过」的条件必须有责任人、截止日期和验证方式。

## 8. 异常与升级

| 情况 | 处理 |
|---|---|
| 工具不可用/权限被拒 | 按 `CLAUDE.md` Hard stop 1 停止并报告，不绕路 |
| jlceda skill 能力不足 | 记录为 RISK-07，暂停该操作，向鼠王报告；不得改用桌面自动化绕过 |
| 工程师朋友不可用 | 门保持关闭，不得跳过终审 |
| 预审与终审意见冲突 | 跑实际检查（ERC/DRC/实测），以结果为准 |
| 关键物料缺货 | BOM 阶段给出替代料；未确认前不得下单 |
| 需求互相冲突（如延迟 vs 低频音质） | 回到 G0，由鼠王裁决并记录 ADR |

## 9. headless 运行约定

本项目常由 Grok Bot / DSH 以 `claude -p` 调用：

- 不向用户提问；信息缺失时取最安全合理路径，并在报告 NOTES 中注明假设。
- 不执行下单、付款、删除、关闭应用等不可逆动作；只准备并报告。
- 汇报固定四段：STATUS / CHANGED / VERIFY / NOTES。
